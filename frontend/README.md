# R.HA 프론트엔드

React + TypeScript + Vite + Tailwind CSS 4, shadcn/ui의 Radix 기반 `radix-nova` 스타일을 사용한다.

## 실행

```bash
cd frontend
npm install
npm run dev
```

## 관리자 실제 API 연결 (2026-10-15)

`npm run dev`는 DB 없이 사용할 수 있는 미리보기 모드다. 로그인 화면의 **회원 화면 열기 / 강사 화면 열기 / 관리자 화면 열기** 버튼으로 바로 들어갈 수 있다. 관리자 예시 계정(`admin@rha.example` / `RhaDemo123!`)을 직접 입력해도 된다. 회원가입은 필요하지 않다.

실제 연동은 백엔드·DB·관리자 계정을 준비한 뒤 `npm run dev:api`로 실행한다. 백엔드를 `http://localhost:8080`에서 실행하면 Vite가 `/v1` 요청을 전달한다. 실제 관리자 계정으로 로그인하며 토큰 갱신·새로고침 세션 복원·로그아웃을 지원한다. 다른 백엔드는 `.env.local`의 `API_PROXY_TARGET`으로 설정한다. 배포에서는 같은 출처의 `/v1` 프록시와 HTTPS를 구성한다. 프로덕션 빌드는 항상 실제 API를 사용한다.

미리보기 버튼은 모의 모드에서만 표시한다. 아래의 과거 미리보기 설명은 모의 모드 기준이다. 모드 변경 시 개발 서버를 재시작한다.

- 타입체크: `npm run typecheck`
- 테스트: `npm test`
- 빌드: `npm run build`
- 코드 정리: `npm run format` (검사: `npm run format:check`)
- API 재생성: `npm run generate:api` (`../api-spec/openapi.yaml` 기준)
- [연동 범위·없는 API·실행 및 검증 기록](../docs/admin-api-integration.md)

실제 메일 발송과 초기 관리자 계정 준비는 백엔드 후속 작업이다. 인증/초대/재설정 API는 존재하지만 현재 메일러는 개발 로그만 출력한다.

코드 형식은 `.prettierrc.json`을 따른다. API 생성 코드(`src/api/generated/`)는 포맷 대상에서 제외하고, 수업 화면의 주 이동·월 선택은 `WeekToolbarControls`를 공유한다.

## 강사 실제 API 연결 (2026-10-22)

강사 홈·담당 수업·예약자·출결·부재 신청은 기존 백엔드 API를 사용한다. 실제 강사 계정으로 `npm run dev:api`에서 로그인하면 된다. 별도 `MEMBER_READ` 권한 없이 담당 수업별 예약자를 조회한다. `npm run dev`에서는 같은 생성 훅을 MSW로 처리한다.

홈은 현재 서울 날짜의 담당 수업과 출결 대기, 본인 부재 승인 대기를 집계한다. 부재 신청·철회는 서버에 저장하며 실패 시 입력과 오류를 유지한다. 출결 상태는 서버에 저장되지만 **정정 사유는 현행 계약에 필드가 없어 현재 로그인 세션의 화면에서만 보관**한다. 새로고침하면 사유와 화면 이력은 초기화된다.

아래의 과거 UI 검토 설명 중 강사 홈·부재의 메모리 데이터 설명은 당시 기록이다. 현재 연결 범위와 검증은 [강사 API 연동 기록](../docs/instructor-api-integration.md)을 따른다.

## 공통 UI

- 화면 구성: `../docs/wireframes/wireframes.html`
- 컴포넌트 사용 규칙: `../docs/shadcn-ui-component-guide.md`
- 업무 메뉴: `../docs/menu-structure.md`
- 역할별 메뉴 설정: `src/config/access.ts`. 메뉴 순서·노출 역할·권한·역할별 이름·상세 화면 관계를 관리한다. 관리 방법과 예시 권한의 범위는 `../docs/navigation-management.md` 참고.
- shadcn 설정: `components.json`. 부품은 `@/components/ui/*`에서 가져온다.
- 부품 추가: `npx shadcn@latest add <컴포넌트명>`. 공통 부품과 설정은 Git으로 공유하며 기존 부품을 덮어쓰기 전에 변경 내용을 확인한다.
- 전역 토큰·기본 스타일: `src/globals.css`. 색상·간격·radius·글꼴 크기의 공통 값은 여기에서 조절한다. 본문 15px, 보조 설명 13px, 기본 컨트롤 높이 44px·작은 버튼 40px, 카드 그림자 없음.
- 화면 전용 스타일: 인증은 `src/features/auth/auth.css`, 회원 메뉴는 `src/features/member/member.css`, 회원 홈은 `src/features/dashboard/member-home.css`, 강사·관리자 대시보드는 `src/features/dashboard/dashboard.css`, 강사 업무 메뉴는 `src/features/instructor/instructor.css`, 홈 로딩·오류 상태는 `src/features/dashboard/dashboard-state.css`에서 관리한다. 각 스타일 파일은 해당 화면 컴포넌트가 가져온다.
- 공통 부품 스타일: 로고·버튼·상태 배지·표·대화상자는 해당 컴포넌트 옆 CSS에서 관리한다. 반복되는 표현은 컴포넌트 variant로 추가하고, 색상·간격·radius 값은 전역 토큰을 사용한다.
- 앱 셸은 `src/app/shell.css`, 이전 화면에서 쓰는 규칙은 `src/app/legacy.css`에 둔다. `src/main.tsx`는 전역 토큰을 먼저 불러와 스타일 레이어 순서를 고정한다.
- 회원·강사·관리자 홈도 업무 메뉴와 같은 페이지 여백·타이포그래피·카드 토큰을 사용한다. 역할별 콘텐츠 배치는 각 화면 CSS에서 관리하고, 화면 높이에 맞춰 글자나 버튼을 축소하지 않는다.
- 홈과 업무 화면의 제목은 24px/굵기 500, 본문 15px, 보조 설명 13px, 요약 숫자는 30px/굵기 300을 사용한다. 페이지 여백은 데스크톱 세로 36px·가로 40px, 모바일 세로 24px·가로 16px이며 카드 여백은 20px·모바일 16px이다.
- 기존 회원 화면 스타일은 `src/app/legacy.css`의 `legacy` 레이어 안 `.member-preview` 범위에 둔다.

## 인증 화면과 미리보기

첫 화면은 로그인이다. 인증 화면은 React Hook Form과 shadcn의 Card, Field, Input, Button, Alert를 사용한다. 계정 메뉴는 DropdownMenu, 로그아웃 확인은 AlertDialog, 결과 알림은 Sonner를 사용한다. 장식 아이콘은 표시하지 않는다.

메뉴 1의 로그인, 이메일 인증, 회원가입, 비밀번호 재설정 요청/새 비밀번호 설정, 로그아웃 흐름을 메모리 예시 데이터로 제공한다. API와 실제 이메일 발송은 연결하지 않았으며 입력값과 계정은 새로고침하면 초기화된다. 인증 관련 네트워크 요청과 브라우저 저장소 사용은 없다. 실제 API 연동 시 OpenAPI로 생성한 훅을 사용해야 한다.

- 예시 계정: `demo@rha.example` / `RhaDemo123!`.
- 이메일 인증: 새 이메일로 코드를 요청하면 화면 아래에 미리보기 코드가 표시된다. 재요청하면 이전 코드는 무효화된다.
- 회원가입: 인증된 이메일, 이름, 생년월일, 휴대전화, 8~64자 비밀번호가 필수다. 주소는 선택이며 역할은 항상 MEMBER다.
- 비밀번호 재설정: 가입 여부와 관계없이 같은 접수 안내를 표시한다. `재설정 메일 링크 미리보기`로 새 비밀번호 화면을 확인한다. 등록된 예시 계정에만 변경을 적용한다.
- 로그아웃: 계정 메뉴 또는 상단 버튼에서 확인 후 로그인 화면으로 돌아간다. 취소하면 기존 화면을 유지한다.
- 예시 코드 유효 시간 5분, 가입 인증 토큰과 재설정 링크 유효 시간 30분은 **미리보기용 값**이며 실제 서버 정책은 별도다.
- 로그인 결과의 역할에 따라 회원·강사·관리자 홈을 표시한다. 회원가입은 항상 MEMBER이며, 비밀번호 재설정은 기존 역할을 유지한다. 로그인 아래의 역할별 미리보기 버튼으로 각 홈을 바로 확인할 수 있다.

## 역할별 홈과 내비게이션

메뉴 구조도 2번과 UI 가이드에 따라 회원·강사·관리자 홈을 공통 셸과 Card/StatusBadge로 구성한다.

- 회원: 공개 수업 페이지당 최대 5개, 내가 예약한 수업 페이지당 최대 3개(항상 3칸), 내 이용권과 예약·대기·잔여·지난 기록 요약. 알림 수는 헤더와 메뉴에서 확인하며 홈에 최근 알림·빠른 메뉴는 두지 않는다.
- 강사: 오늘 담당 수업, 담당 수업의 예약·출결, 종료된 수업의 출결 처리 대기, 내 부재 승인 대기, 내 알림. 사이드바에 별도 `출결` 메뉴를 두지 않고 `오늘 담당 수업` 상세에서 처리·정정을 제공한다. `부재 신청`은 독립 메뉴로 표시한다. 각 화면의 기존 접근 권한을 유지한다.
- 관리자: 오늘 전체 수업, 전체 예약·출결, 강사 부재 승인 대기, 내 알림.
- 요약 지표와 전체 보기에서 해당 조회 화면으로 이동한다. 수업별 예약자·출결과 회원 홈 공개 수업은 Table, 회원 수업 탐색 메뉴도 항목별 한 줄의 Table 목록이다. 알림은 생성된 API 훅으로 조회하고 중앙 Radix Dialog에서 읽음 처리하며 헤더·메뉴·홈의 미읽음 수를 함께 갱신한다.
- 신규 가입 계정은 기존 예시 회원의 수업·이용권·알림을 홈에 표시하지 않는다.

`src/features/dashboard/preview.ts`는 2026-10-13 12:00 서울 시각의 고정 예시 데이터이며 화면에도 예시 기준을 표시한다. `model.ts`에서 서울 날짜 경계, 역할과 사용자 ID, 예약·출결 상태로 필터링·집계한다. 실제 API/MSW 연동과 출결 저장·부재 승인/반려는 연결하지 않았다. 별도 대시보드 API를 추가하지 않았으며 이후 `wireframe-api-mapping.md`에 정의된 기존 API의 생성 훅으로 교체한다.

예시 계정의 비밀번호는 모두 `RhaDemo123!`이다.

| 역할 | 이메일 |
|---|---|
| 회원 | `demo@rha.example` |
| 강사 | `instructor@rha.example` |
| 관리자 | `admin@rha.example` |

공통 내비게이션은 shadcn의 SidebarProvider, Sidebar, SidebarMenuButton을 사용한다. 프로젝트 공통 `brand` variant는 연한 그린 배경과 굵은 텍스트로 선택 상태를 표시하고 장식 아이콘이나 왼쪽 강조선을 사용하지 않는다. 모바일은 Sidebar가 제공하는 열림 상태와 텍스트 메뉴 열기/닫기 버튼을 사용한다. Sheet는 Sidebar의 내부 의존성이며 업무 상세/폼에는 사용하지 않는다.

## 메뉴 1·2 UI 검토 범위

- 와이어프레임의 화면 구조를 `docs/shadcn-ui-component-guide.md`의 shadcn 컴포넌트·variant·토큰으로 구현한다.
- 로그인 아래 `홈 화면 상태 선택`을 펼쳐 정상/불러오는 중/데이터 없음/조회 실패/로그인 만료/권한 없음을 선택하고 역할별 미리보기를 연다.
- 로딩은 화면 검토를 위해 유지된다. 계정 메뉴의 로그아웃으로 돌아갈 수 있다. 조회 실패의 `다시 시도`는 정상 예시로 전환하고, 만료/권한 없음의 로그인 복귀는 로그인 화면을 연다.
- 인증은 기존 로컬 예시의 입력 검증·제출 중·실패·성공 화면으로 검토한다. 실제 메일·세션·네트워크 동작을 의미하지 않는다.
- 사용자가 확정한 회원 홈 5개/3칸 배치, 로고, 오른쪽 범례, 강조된 표 제목 행을 유지한다. 로그인 로고는 원본이고 사이드바는 별도 문구를 사용한다.
- 완료 범위는 UI 디자인과 예시 화면 전환이다. API 생성 훅·MSW·백엔드·실제 이메일 발송은 이번 작업 범위에 포함하지 않는다.

## 관리자 업무 화면 (2026-10-13)

로그인 화면의 **관리자 화면 열기**, 또는 `admin@rha.example` / `RhaDemo123!`로 확인한다.

- 회원 관리: 이름·이메일 검색, 상태·페이지, 기본 정보·상태 변경, 상세의 이용권·예약·출결·결제.
- 강사 관리: 등록·정보·상태·권한 전체 교체·가능시간, 부재 목록·상세·승인·반려·취소·영향 수업 연결, 퇴사일·수업 인계·퇴사 처리·퇴사자 정산 연결.
- 수업 운영: 회차 필터·목록·상세, 개설·수정·공개/비공개·공개 예약·취소, 예약 목록·상세·취소·출석·노쇼·출결 정정.
- 회원 이용권: 전체/회원별 조회, 새 발급·재등록, 잔여·만료일·강사 조정, 홀딩 등록·예정·해제, 결제 기록·수정·삭제·환불 여부 기록.
- 스튜디오 설정: 운영 기본 설정에서 예약 정책·영업시간을 바로 편집하고 상품·유형·룸 현황을 확인한다. 상품 등록·수정·발급분 영향 확인·삭제, 수업 유형 등록·수정·활성 상태, 룸 등록·수정·사용 수업 확인·삭제, 요일별 영업시간·예약 정책.
- 강사 수당·정산: 유형별 단가, 기간 계산, 수업별 항목, 검토·확정·지급 사실 기록·미확정 정산 폐기, 처리 이력.
- 관리자 본인 알림·미읽음 수·개별/전체 읽음, 활동 이력 필터·변경 전후·관련 화면.

기존 `MenuPanel`, `Table`, `StatusBadge`, `Tabs`, 중앙 Dialog/AlertDialog와 전역 토큰을 사용한다. 기존 회원·강사 홈 배치를 유지하고 관리자 홈 데이터만 관리자 조회 결과에 연결한다.

## 메뉴 11 강사 업무 UI

- 강사 사이드바의 `오늘 담당 수업`, `수업별 예약자`, `부재 신청`에서 확인한다. 와이어프레임의 메뉴 5·6 및 `11-role-menu-instructor-api.md` 기준이다.
- `src/features/instructor/`에 화면·UI 검증용 데이터·상태 제한을 분리했다. 화면 스타일은 `instructor.css`, 공통 입력/대화상자 스타일은 해당 컴포넌트 옆 CSS에 둔다. 기존 전역 토큰을 사용한다.
- 담당 수업 조회와 예약 상세, 출석·노쇼 확인, 정정 사유 입력과 이력, 부재 신청·상세·승인 전 철회를 제공한다. 표 열 제목은 가운데 정렬하며 정렬 가능한 열에 오름차순/내림차순을 제공한다.
- 출결은 시작한 본인 담당 수업만 처리한다. 취소 예약과 UI 예시에서 정산된 수업은 변경하지 못한다. 별도 출결 정정 요청·승인 절차는 현행 계약에 없어 직접 정정 화면으로 구현했다.
- 부재는 서울 일시를 UTC로 변환하며 과거·역순·중복 기간을 검증한다. 승인된 부재의 철회나 관리자 승인/반려 기능은 강사 화면에 제공하지 않는다.
- UI 변경은 로그인한 미리보기 세션의 메모리에서 유지되고 홈 지표에도 반영된다. 새로고침·로그아웃 시 초기화하며 서버 저장·API·MSW 연동은 없다. 기준 시각은 기존 대시보드와 같은 2026-10-13 12:00 서울이다.
- 정산 잠금, 사용 이용권 이름, 정정 사유·이력은 UI 검토용 데이터다. 실제 연동 시 계약에 없는 정산 플래그·정정 사유·이력을 API에서 제공한다고 가정하지 않는다.

### 강사 출결 통합 (2026-10-15)
- 오늘 담당 수업 → 상세 보기의 예약자 표에서 출석·노쇼를 기록한다. 시간 다음 열은 처리 → 상세 보기 → 출결 상태다. 미처리 상태는 빈 칸이다.
- 기록 후에는 `출결 수정`에서 변경할 상태와 필수 정정 사유를 입력한다. 수업별 예약자에서 이어지는 출결 화면에서도 같은 상태와 정정 이력을 확인한다. 사이드바의 별도 출결 항목은 표시하지 않는다.
- 이 흐름은 기존 강사 UI 미리보기의 메모리 상태를 공유한다. 새로고침하면 초기화된다. 실제 저장 API와 정정 사유 계약은 이번 변경에 포함하지 않는다.
- 회원 홈 공개 수업·예약 목록은 바깥 세로 여백을 0으로 두고 각 행의 상하 여백에 `--space-detail`을 적용한다. 첫·마지막 행에도 동일한 행 간격을 사용한다. 공개 수업 5칸, 예약 3칸, 담당 수업 5칸은 유지한다.

- 데스크톱 회원 홈(너비 1100px·높이 700px 이상)은 뷰포트 높이에 맞춘 압축 레이아웃을 사용한다. 홈 행 상하 간격은 모두 `--space-control`이며 목록 밖 여백은 0이다. 좁은 화면에서는 자연스럽게 스크롤한다.
- 수업별 예약자 화면의 별도 수업 요약 카드와 담당 수업 건수·서울 시간 문구를 제거했다. 예약자 제목 아래 `ReservationSummary`로 예약·출석(초록)·노쇼(빨강)를 표시한다. 관리자 수업 상세의 예약자 목록도 같은 요약 컴포넌트를 사용한다.
- 회원 홈 공개 수업은 날짜·시간·수업명·담당 강사·룸·예약 인원·상태·상세를 별도 열로 표시한다. 각 셀은 한 줄로 유지하고 상세 보기는 공통 outline 버튼을 사용한다.

- 목록은 페이지당 최대 5개를 표시하고 초과하면 기존 `Pagination`의 이전·다음 버튼으로 이동한다. 회원 홈의 내가 예약한 수업만 페이지당 3개이며 부족한 슬롯은 빈 행으로 유지한다. 서버 페이지 목록은 `size: PAGE_SIZE`와 응답 `pageInfo`를 사용한다.

- 회원 홈 예약 목록은 3개씩 페이지 이동하며 이전·다음 버튼을 항상 표시한다. 이동할 페이지가 없으면 비활성화한다. 회원 수업 목록은 날짜·시간·수업명·담당 강사·룸·예약 인원·상태·상세·신청을 각각 별도 열에 표시한다.

- 회원 내 예약·출결은 페이지당 5개씩 표시하고 이전·다음으로 이동한다. 수업명 아래 예약 번호는 표시하지 않으며, 표의 열 너비와 내부 간격을 동일하게 맞춘다. 작은 화면은 표 내부에서 가로 스크롤한다.

- 강사·관리자 홈은 압축 레이아웃 적용 이전의 카드 높이·여백·글자 크기로 복원했다. 업무 메뉴와 같은 페이지·표 토큰을 사용하며 내용이 길면 자연스럽게 스크롤한다. 목록 페이지 이동과 강사 출결 통합은 유지한다.
- 강사·관리자 홈의 최근 알림은 페이지 이동 대신 내부 세로 스크롤로 표시하며, 조회된 알림을 6개로 자르지 않는다. 상세 보기 버튼은 수업 목록과 같은 `outline`/`table-action`을 사용한다.
- 강사 홈의 오늘 담당 수업과 내 부재 승인 대기는 5개씩 표시하고, 목록이 있으면 공통 이전·다음 버튼을 항상 표시한다. 6개 이상일 때 다음 페이지로 이동할 수 있으며, 이동할 페이지가 없으면 해당 버튼을 비활성화한다.
